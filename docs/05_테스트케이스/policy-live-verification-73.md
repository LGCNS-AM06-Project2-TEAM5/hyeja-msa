## 검증 환경과 범위

로컬 MariaDB `13.0.2`, `127.0.0.1:3307`에 독립 스키마 `policy_verify73_f3cd7e`와 해당 스키마만 사용하는 임시 계정을 만들었다.
기존 `policy_db` 및 다른 서비스 DB는 변경하지 않았다. Java 17로 빌드한 실제 bootJar를 dev 프로필로 실행했다.
Config Server·Eureka·트레이싱은 검증 실행 환경에서 비활성화하고, 서버는 loopback 주소에만 바인딩했다.
지역 CSV 256건과 용어 시드 50건이 실제 MariaDB에 적재되는지 확인했다.

온통청년 공식 API는 실제 키로 호출했으며 HTTP 200 / resultCode 200, 1페이지 100건을 받았다.
승인 코드는 실제 응답의 `0044002`이며 기존 Java 변환기가 선행 0을 제거하여 정상 판정한다.

**전체 3,840건 수집이나 공식 URL에 직접 연결한 무제한 `/sync` 실행은 이번 검증 범위가 아니다.**
로컬의 검증 전용 중계 서버가 매 수집 요청마다 공식 API의 실제 1페이지를 조회한 뒤,
주거 3건과 비주거 1건만 전달했다. 각 정책의 원문 필드는 변경하지 않았고 정책 목록·페이지 메타데이터만
검증 범위에 맞춰 제한했다. 실행 환경의 `YOUTH_API_URL`만 중계 주소로 지정했으며 서비스 소스·기본 URL은 바꾸지 않았다.
비주거 정책은 기존 수집 필터에서 제외되어 실제 OpenAI 분석은 회차당 3건, 총 6건 실행됐다.
중계는 비용과 범위를 제한하는 검증 도구이며, 모든 페이지의 수집 성공을 증명하지 않는다.

## 재검증 절차

1. 별도 검증 DB·계정을 준비하고 `POLICY_DB_URL`, `POLICY_DB_USERNAME`, `POLICY_DB_PASSWORD`를 실행 환경으로 주입한다.
2. 실제 `YOUTH_API_KEY`, `OPEN_AI_KEY`, `OPEN_AI_MODEL`을 주입한다. `.env`는 Spring Boot가 자동 로딩하지 않는다.
3. dev 프로필로 빌드된 서버를 실행한다. 공유 DB로 잘못 연결되지 않도록 대상 스키마를 먼저 확인한다.
4. 소량 검증은 위와 같은 로컬 중계로 공식 원문 정책 목록·페이지 수만 제한한다. 기본 공식 URL을 그대로 쓰면 전체 수집이 실행될 수 있다.
5. 검증용 관리자 헤더로 `/sync`를 1회 호출하고 아래 SQL로 저장 결과를 확인한다.
6. 같은 범위로 재호출하여 카드 ID·본문과 지역 연결을 비교한다. 정책명·지역 연결 변경 실험은 검증 DB에서만 수행한다.
7. `/housing`, `/{policyId}`, `/card-detail/{policyId}`, F2·F5를 호출하고 DB 결과와 비교한다.

```sql
SELECT COUNT(*) FROM policy;
SELECT COUNT(*) FROM policy_region;
SELECT COUNT(*) FROM card_news;
SELECT policy_id, COUNT(*) AS cards
FROM card_news GROUP BY policy_id;
SELECT policy_id, card_no, COUNT(*) AS duplicates
FROM card_news GROUP BY policy_id, card_no HAVING COUNT(*) > 1;
SELECT policy_id, policy_name, category, apply_period_code, apply_start_date, apply_end_date
FROM policy ORDER BY policy_id;
```

검증에 사용한 중계·실행 도구는 로컬 임시 도구이며 저장소에 추가하지 않았다.
같은 33개 단언을 명령 한 번으로 재현하는 상시 테스트는 이번 산출물에 포함하지 않는다.
API 키·DB 자격증명·원문 실행 로그는 이 문서와 Git에 저장하지 않는다.

## 종료 상태와 미검증 범위

- 검증용 Policy 프로세스와 중계 서버는 종료했다.
- 임시 경계 데이터와 상태 변경은 정리했고, 독립 DB에는 실제 정책 3건·지역 연결 49건·카드 12건을 보존했다.
- 소스 코드·의존성·공통 실행 설정 변경 없음. 이번 저장소 변경은 검증 결과 문서와 테스트 문서 인덱스뿐이다.
- 공식 API 전량/다중 페이지 수집, 실제 페이지 실패·재시도, 전체 대량 수집 처리 시간은 미검증이다.
- Recommendation·Engagement의 실제 Feign 호출·내부 서비스 인증, 실제 User 호출, Gateway·프런트 흐름은 미검증이다.
- policy-updated/Kafka/Outbox 및 배포 환경도 이번 범위에 포함하지 않았다.
- 서비스 코드의 신규 결함은 이번 샘플에서 발견하지 않았다. 통과는 위 환경·데이터·범위에 한정한다.

후속 작업은 실제 서비스 간 F2·F5 연동, 내부 인증 합의, Gateway 사용자 흐름 통합 검증이다.
