# 협업 규칙

혜자 규칙([hyeja-backend/docs/development-workflow.md](https://github.com/LGCNS-AM06-Project2-TEAM5/hyeja-backend/blob/main/docs/development-workflow.md))을 이어서 씁니다.

## 기본 흐름

```text
이슈 생성 → develop에서 작업 브랜치 → 작은 커밋 → 테스트 → develop 최신 반영 → push → develop으로 PR → 리뷰·CI → merge
```

## 브랜치

| 브랜치 | 용도 | 직접 push |
|---|---|---|
| `main` | 발표·제출용 최종본. `develop` → `main` PR로만 반영 | 금지 |
| `develop` | 기본 브랜치. 통합 개발본 | 금지 (PR로만) |
| `<tag>/<이슈번호>/<영문-설명>` | 각자 작업 | 자유 |

예: `feat/12/member-service-split`, `infra/3/eureka-server`, `docs/20/system-diagram`

## 커밋

```text
<tag> : <변경 내용>
```

tag: `feat`, `fix`, `refactor`, `chore`, `docs`, `test`, `infra`

## PR

- 대상 브랜치가 `develop`인지 확인합니다.
- 본문에 `Closes #이슈번호`를 넣습니다.
- 리뷰 1명 이상 승인과 CI 통과 후 merge합니다.
- 다른 서비스의 API나 Kafka 이벤트 형식을 바꾸면 [api/README.md](api/README.md)를 같은 PR에서 고칩니다.

## 라벨

PR과 이슈에 **작업 종류 1개 + 영역 1개 이상**을 붙입니다.

| 종류 | 영역 |
|---|---|
| `feat`, `fix`, `refactor`, `chore`, `docs`, `test`, `infra` | `member`, `policy`, `ai`, `favorite`, `notification`, `gateway`, `discovery`, `config`, `kafka`, `docker`, `k8s`, `frontend`, `산출물` |

## 비밀값

- `.env`, API 키, 비밀번호, Gmail 앱 비밀번호는 커밋하지 않습니다. `.env.example`에 이름만 적습니다.
- Config 저장소(hyeja-config)에 넣는 비밀값은 `{cipher}`로 암호화합니다.
- CI에 필요한 값은 저장소 Settings → Secrets and variables → Actions에 등록합니다.

## 커밋 작성자 규칙

- 커밋 작성자와 공동 작성자는 팀원만 남깁니다.
- AI 도구가 붙이는 `Co-authored-by`, `Generated with` 같은 줄이나 AI 도구가 작성자로 된 커밋을 올리면, `commit-check`가 **자동으로 정리해 같은 브랜치에 다시 올립니다.** PR 설명의 생성 표시도 자동으로 지웁니다.
- 자동 정리가 일어나면 GitHub의 브랜치 기록이 바뀌므로, 로컬에서 이어서 작업하기 전에 `git pull --rebase`로 받아 주세요.
- (선택) 커밋할 때부터 지우고 싶으면 `git config core.hooksPath .githooks`를 한 번 실행합니다.

## 저장소 역할

| 저장소 | 역할 |
|---|---|
| `hyeja-msa` | MSA 작업 저장소 (Eureka·Gateway·Config, 서비스, Docker Compose, 문서) |
| `hyeja-backend` | 혜자 백엔드 코드. 서비스로 나눌 코드를 가져오는 곳 |
| `hyeja-frontend` | 혜자 프런트엔드. Gateway 연결과 화면 수정 |
| `hyeja-config` | Config Server 설정 파일 |
